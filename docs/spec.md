# Leinwand 仕様書

2026-10-02

Leinwand(ドイツ語で「キャンバス」)は、デスクトップ向けに、Illustrator相当の機能を最終目標とするベクターグラフィックエディタを趣味・学習目的で作る。重点はパス編集・文字組み・ファイル互換の3領域。決定事項の一覧と残りの未決事項は10章にまとめる。

| 章 | 内容 |
| --- | --- |
| 1. 概要 | 目的、前提、やらないこと、公開とライセンス |
| 2. 技術スタック | C++ + Skia + Qt Quick、GPU描画、使用ライブラリ |
| 3. ドキュメントモデル | オブジェクト構造、カラー、.lwd 形式とJSONの構造、保存 |
| 4. パス編集 | 重点領域。データモデル、ツールの操作、パス演算 |
| 5. 文字組み | 重点領域。テキストエンジン、フォント管理、行分割 |
| 6. ファイル互換 | 重点領域。SVG、PDF、.ai、読み込みレポート |
| 7. 機能一覧とUI | 機能とフェーズの対応、デザイン言語、メニュー、パネル、環境設定、プリント、入稿と制作支援 |
| 8. 開発フェーズ | 5つのフェーズと各到達点 |

## 1. 概要

作ること自体と、自分で使える道具に育てることの両方を目的とする。締め切りや商用要件はなく、設計の正しさと学びを優先する。

**前提**

- 対象環境はデスクトップ。対象OSはWindows・Linux・macOSの3つ。最初はWindowsで開発し、Linux、macOSの順に対応する。ただしmacOSは、フェーズ2の前にビルドとテスト(Metal描画)と試用版のディスクイメージまで進める(2026-10-03 決定)。Linuxでは X11 と Wayland の両方、フォント列挙は Fontconfig を前提にする。OS固有の処理(IME、クリップボード、ファイルダイアログ)は抽象化層の裏に置く。フォント列挙はSkiaのフォント管理(DirectWrite、Core Text、Fontconfig)を使い、Skiaに依存しないインターフェースの裏に置く(M8の検証)。マウス+キーボード操作を基本とし、ペンタブレットの筆圧は後のフェーズで対応する。
- 最終目標はIllustrator相当だが、一度に作らない。フェーズを区切り、各フェーズ終了時点で「使える」状態にする。
- 重点3領域(パス編集・文字組み・ファイル互換)は、他の機能より先に深く作り込む。

**やらないこと(当面)**

- 共同編集、クラウド同期、アカウント機能
- 3D効果、AI生成機能、画像トレース
- プラグインAPIの公開(内部の拡張ポイントは設計するが、外部公開はしない)
- .ai のネイティブ形式での書き出し(理由は6章)

**公開とライセンス**

ソースコードはGitHubで公開し、オープンソースとして開発する。リリースの成果物も同じリポジトリのGitHub Releasesに置く。外部からのプルリクエストは当面受け付けず、不具合報告や要望はIssueで受ける。

| 部品 | ライセンス | 扱い |
| --- | --- | --- |
| Qt | LGPLv3 | 動的リンクで使う。GPL専用のQtモジュールは使わない |
| Skia、PDFium | BSD系 | 著作権表示を同梱 |
| HarfBuzz、Little CMS | MIT系 | 著作権表示を同梱 |
| FreeType、ICU | 独自の寛容なライセンス | 著作権表示を同梱 |
| Spectrumのデザイントークン | Apache License 2.0 | NOTICEを同梱 |

Leinwand自体のライセンスは「GPLv3またはそれ以降」(GPL-3.0-or-later)とする。Apache 2.0の部品(Spectrumのデザイントークン)と両立するのはGPLv3からのため、GPLv2は選ばない。配布物には、使用ライブラリのライセンス文をまとめた一覧を同梱し、アプリ内の「Leinwandについて」から表示できるようにする。

## 2. 技術スタック

技術スタックはB案(C++ + Skia + Qt)に決定した。検討した4案はこの章の末尾に記録する。どの案でも、描画・ドキュメントモデル・UIの3層を分離し、モデル層はUIに依存させない。

**UI層: Qt Quick(QML)**

UIはQt Quickで組む。パネルやツールバーはQML、ドキュメントモデルと描画はC++で書き、QMLからはC++側のモデルを参照するだけにする。

- キャンバス: Skiaの描画結果をQt Quickのシーングラフに1つの描画ノードとして組み込む。SkiaとQt Quickで同じGPUバックエンドを共有できるかをフェーズ1で検証する。
- 選択枠・ハンドル・ガイドなどのオーバーレイもSkia側で描く。QMLの要素にするとズーム時の追従が遅れるため。
- ドッキングパネル: Qt Quickには標準機能がない。KDDockWidgets(KDAB製、Qt Quick対応、GPL 2.0 または GPL 3.0)を使う。M0で見た目をSpectrumに合わせられることを確かめた。ただしWindowsのVulkanでは半透明ウィンドウが黒くなるため、ドロップ表示をウィンドウ内に描くパッチを当てて使う。KDDockWidgetsを組み込んだ配布物は、全体としてGPLv3でのみ配布できる。詳細は [m0-verification.md](m0-verification.md) と [implementation-notes.md](implementation-notes.md)。
- テキスト入力: キャンバス上の文字編集は独自のテキストエンジン(5章)で行い、IMEとの橋渡しだけQtの入力メソッドAPIを使う。

**描画バックエンド: GPU**

最初からSkiaのGPU描画を使う。APIはVulkanを第一候補とし、WindowsとLinuxで共通のコードにする。macOS対応時にMetalを追加する。GPUが使えない環境向けのCPU描画は、書き出し処理(PNG・PDF)で使う経路を流用する。

**クラッシュレポーターとログ**

クラッシュの検知と報告は、本体とは別のプロセスで行う。本体が異常終了しても、レポーターは生きていて詳細を表示できる。

- Leinwandの起動時に、監視用のプロセス(クラッシュレポーター)を一緒に立ち上げる。クラッシュの捕捉にはCrashpad(Apache License 2.0)を第一候補とする。
- 本体が異常終了すると、レポーターがダイアログを表示する。内容は、エラーの種類と発生箇所、スタックトレース、直前のログ、環境情報(Leinwandのバージョン、OS、GPUとドライバー、メモリ)。
- ダイアログの操作: 詳細の表示切り替え、内容をコピー、レポートをファイルに保存、GitHubのIssue作成ページを開く、Leinwandを再起動。
- レポートは自動では送信しない。送るかどうかは利用者が決める。ドキュメントの内容やファイルのパスはレポートに含めない。
- 再起動すると、自動保存の復元(3.3)につながる。
- スタックトレースを読める形にするため、リリースごとのデバッグシンボルをGitHub Releasesに添付する。
- ログは通常時も設定フォルダに書き出す。レベルは エラー / 警告 / 情報 / デバッグ。ファイルは起動ごとに分け、古いものから削除する。ヘルプメニューからログのフォルダを開ける。
- GPUの初期化失敗など、クラッシュではない致命的なエラーも同じダイアログで表示する。

**共通で使う想定のライブラリ**

| 用途 | 候補 |
| --- | --- |
| テキストシェーピング | HarfBuzz |
| フォント読み込み・ラスタライズ | FreeType、またはOS標準API |
| Unicode処理(改行位置、双方向) | ICU |
| カラーマネジメント(ICC、CMYK) | Little CMS |
| PDF読み込み | PDFium(MuPDFはAGPLのため公開時に注意) |

**検討した4案(記録)**

| 案 | 構成 | 強み | 弱み |
| --- | --- | --- | --- |
| A | Rust + wgpu + 自前UIまたは既存GUIライブラリ | 性能、メモリ安全、ベクター系ライブラリ(kurbo等)が揃う | UIライブラリが発展途上で、複雑なパネルUIは自作が多い |
| B | C++ + Skia + Qt | 実績が最も多い。Skiaはパス演算・PDF出力・テキスト描画を内蔵 | ビルド環境が重い。メモリ管理の負担 |
| C | Kotlin + Compose Multiplatform(Desktop) | UI構築が速い。内部でSkiaを使うため描画品質は高い | 大量オブジェクト時の性能と、低レベル描画APIへのアクセスに制約 |
| D | TypeScript + Tauri/Electron + WebGPU/Canvas | UI開発が最も速い。将来Web版に転用できる | 巨大ドキュメントの性能、フォント・カラーマネジメントの制約 |

## 3. ドキュメントモデル

ドキュメントは「アートボードの集合」と「レイヤーツリー」を別々に持つ。Illustratorと同じく、アートボードは書き出し範囲を示す枠であり、オブジェクトの親にはならない。

**階層**

1. ドキュメント(カラーモード RGB/CMYK、単位、カラープロファイル、スウォッチ、シンボル、スタイル定義)
2. レイヤー(入れ子可、表示・ロック・書き出し対象フラグ)
3. オブジェクト(下表)

| オブジェクト種別 | 内容 |
| --- | --- |
| パス | アンカーポイント列(3次ベジェ)、開/閉 |
| 複合パス | 複数のサブパス+塗りつぶし規則(非ゼロ / 偶奇) |
| グループ | 子オブジェクトの集合。クリッピンググループを含む |
| テキスト | ポイント文字、エリア内文字、パス上文字(5章) |
| 画像 | 埋め込みまたはリンクのラスター画像 |
| シンボルインスタンス | シンボル定義への参照+変形行列 |

**アピアランス**

各オブジェクトは、塗りと線を1つずつではなく「アピアランススタック」として持つ。スタックは塗り・線・効果の順序付きリストで、複数の塗りや線を重ねられる。これを最初からモデルに入れる。後付けするとファイル形式と描画パイプラインの両方を作り直すことになるため。

**カラー**

モデルは最初からRGB・CMYK・グレースケール・スポットカラーを持てる構造にする。画面表示と編集UIはRGBから作り、CMYKドキュメント(CMYKの編集UIとCMYKのままの出力)はフェーズ3で対応する。ICCプロファイルによる色変換と校正表示はフェーズ4。

- 色の値は「色空間の種別+成分値+不透明度」で保持する。RGBに変換した値だけを保存しない。
- スポットカラーは名前と代替色(CMYKまたはLab)を持つ。
- ドキュメントはカラーモード(RGB / CMYK)とICCプロファイルを持つ。フェーズ1〜2ではRGBドキュメントのみ作成できる。CMYKドキュメントはフェーズ3から。
- CMYK値を持つファイルを読み込んだ場合、値は保持したまま、画面にはRGBへ変換して表示する。

**編集履歴**

- すべての変更はコマンドとして記録し、取り消し/やり直しを無制限に行える。
- モデルは不変データ構造(構造共有)を基本とし、履歴のメモリ消費を抑える。

**ネイティブ保存形式**

独自形式を1つ定める。ZIPコンテナ内に、JSONのドキュメント本体、埋め込み画像、サムネイルを入れる。SVGは変換対象として別に扱い、ネイティブ形式の土台にはしない。サイズや速度が問題になった場合はバイナリ形式への移行を検討する。形式にはバージョン番号を持たせる。

拡張子は `.lwd` とする。同じ拡張子は動画編集ソフトLightworksの内部データや、旧LotusWorksの文書などで使われているが、いずれも利用者が日常的に開くファイルではなく、衝突の影響は小さい([fileinfo.com](https://fileinfo.com/extension/lwd)、[file-extensions.org](https://www.file-extensions.org/extension/lwd))。誤認を防ぐため、ZIP内の先頭に形式識別用のファイルを置き、拡張子だけで判定しない。

### 3.1 ファイルの構造

`.lwd` はZIPコンテナで、中身は次のとおり。

| エントリ | 内容 |
| --- | --- |
| `mimetype` | 形式識別用の文字列。ZIPの先頭に無圧縮で置く。Leinwandはこれを読んで形式を判定する |
| `document.json` | ドキュメント本体(3.2) |
| `images/<ハッシュ値>.<拡張子>` | 埋め込み画像。元のファイル形式のまま格納する。同じ画像は1つだけ持つ |
| `preserved/` | 読み込み時に保持した未対応要素(SVGのXML断片など) |
| `thumbnail.png` | ファイルブラウザとウェルカムスクリーン用のサムネイル(最大512px) |

- `document.json` は人が読める形(インデント付き、キーの順序は固定)で書き出す。差分が取りやすく、バージョン管理に載せられる。
- リンク画像はファイルに含めず、`document.json` にパス(ドキュメントからの相対パスと絶対パスの両方)を記録する。

### 3.2 JSONの構造

共有される定義(スウォッチ、グラデーション、シンボル、スタイル、ストーリー)はトップレベルに置き、オブジェクトからはIDで参照する。

**トップレベル**

| キー | 内容 |
| --- | --- |
| `format` | 形式バージョン(3.3)と、保存したLeinwandのバージョン |
| `settings` | カラーモード、ICCプロファイル名、表示単位、定規の原点、ラスター効果の解像度 |
| `artboards` | アートボードの配列(名前、位置とサイズ、裁ち落とし) |
| `swatches` | スウォッチ(単色、スポットカラー、グラデーション、パターン) |
| `symbols` | シンボル定義(中身はオブジェクトの木) |
| `styles` | グラフィックスタイル、文字スタイル、段落スタイル |
| `stories` | テキストのストーリー(5.1)。`{"id", "text"(UTF-8), "characters": [文字スタイル + "length"], "paragraphs": [段落スタイル + "length"]}`。長さはコードポイント数(段落は改段落を含む)。形式 1.4 で追加 |
| `guides` | ガイド |
| `layers` | レイヤーの木。オブジェクトはこの下にぶら下がる |
| `coverTemplate` | 表紙テンプレートの設定(7.5)。1冊分の幅と高さ、ページ数、本文用紙の厚さ、背幅(直接指定したときだけ)、裁ち落とし。形式 1.1 で追加 |

**オブジェクトの共通フィールド**

| キー | 内容 |
| --- | --- |
| `id` | ドキュメント内で一意の文字列。一度振ったら変えない |
| `type` | `path`、`compoundPath`、`group`、`text`、`image`、`symbolInstance`、`shape`(ライブシェイプ) |
| `name` | レイヤーパネルに出す名前。省略時は種別から自動で付ける |
| `visible`、`locked` | 表示とロック |
| `opacity`、`blendMode` | オブジェクト全体の不透明度と描画モード |
| `appearance` | アピアランススタック。グラフィックスタイルを参照する場合はそのID |
| `mask` | 不透明マスク(形式 1.3 で追加)。`{"object": マスクのオブジェクト, "clip": false, "invert": true}`(`clip` の既定値は true、`invert` は false)。マスクのオブジェクトは、マスクされるオブジェクトと同じ座標系(親の座標系)に置く |

グループは、ほかに `clipped`(最前面の子でクリップする。クリッピングマスク)と `isolated`(描画モードを分離。形式 1.3 で追加)、`outlinedText`(アウトライン化した元のテキストオブジェクト。7.5。形式 1.4 で追加)を持てる。

テキストオブジェクト(`"type": "text"`、形式 1.4 で追加)は `story`(ストーリーの ID)、`transform`(ポイント文字は原点が1行目のベースラインの起点)、`kind`(`point`。省略時)、`orientation`(`horizontal`。省略時)を持つ。古い版が枠を表示できるように `bounds` も書く(読むときは無視して組み直す)。

**色**

色は「色空間 + 成分値」で書く。成分値は0〜1。

| 種別 | 書式 |
| --- | --- |
| RGB | `{"space": "rgb", "values": [r, g, b]}` |
| CMYK | `{"space": "cmyk", "values": [c, m, y, k]}` |
| グレー | `{"space": "gray", "values": [g]}` |
| スポット | `{"space": "spot", "swatch": "<スウォッチID>", "tint": t}` |
| スウォッチ参照 | `{"swatch": "<スウォッチID>"}`(グローバルカラー。スウォッチを変えると追従する) |

**アピアランス**

`appearance` は、前面から背面の順に並べた項目の配列。項目は `fill`、`stroke`、`effect` の3種類で、それぞれが不透明度と描画モードを持てる。

`fill` と `stroke` は `gradient` を持てる(形式 1.2 で追加)。`{"type": "linear" | "radial", "start": [x, y], "end": [x, y], "aspect": 縦横比, "focal": [x, y], "stops": [{"offset", "color", "opacity", "midpoint"}]}`。座標はオブジェクトの座標系。円形では `start` が中心、`end` までの距離が半径で、`aspect` は軸と直交する方向の半径の比。`paint` には先頭の分岐点の色を入れておく(グラデーションを扱えない読み手のため)。

**例: 赤い塗りと黒い線を持つ三角形**

```json
{
  "id": "o7f3k2",
  "type": "path",
  "closed": true,
  "anchors": [
    {"p": [100, 50]},
    {"p": [150, 150]},
    {"p": [50, 150], "in": [20, 0], "out": [0, -30], "kind": "smooth"}
  ],
  "appearance": [
    {"type": "stroke", "paint": {"space": "rgb", "values": [0, 0, 0]},
     "width": 2, "cap": "butt", "join": "miter", "align": "center"},
    {"type": "fill", "paint": {"space": "rgb", "values": [1, 0, 0]}}
  ]
}
```

- 既定値と同じフィールドは省略する(上の例では `visible`、`locked`、`opacity`、ハンドルのないアンカーの `in` と `out`)。
- 数値は必要な精度だけ書く。丸めは小数点以下6桁まで。

### 3.3 バージョン管理と保存

**形式バージョン**

- 形式バージョンは「メジャー.マイナー」の2つの数で表す。アプリのバージョンとは別に管理する。
- マイナーが上がる変更: フィールドや種別の追加。古いLeinwandでも開ける。
- メジャーが上がる変更: 既存フィールドの意味の変更や削除。古いLeinwandは開かず、「新しいバージョンで作られたファイルです」と表示する。
- 新しいLeinwandは、古いメジャーバージョンのファイルを読み込み時に変換して開く。変換処理はバージョンごとに1段ずつ用意し、順に適用する。

**未知のフィールド**

- 読み込み時に知らないフィールドや種別があっても捨てない。そのまま保持し、保存時に書き戻す。
- 知らない種別のオブジェクトは、枠だけのプレースホルダーとして表示する。移動と削除はできるが、編集はできない。
- これにより、新しいバージョンで作ったファイルを古いバージョンで開いて保存しても、情報が失われない。

**保存の手順**

1. 一時ファイルに書き出す。
2. 書き出したファイルを読み直して、ZIPとJSONが壊れていないか確かめる。
3. 元のファイルと置き換える。途中で失敗しても元のファイルは残る。

**自動保存と復元**

- 編集中のドキュメントを、一定間隔(初期設定は2分)で設定フォルダ内の復元用ファイルに書き出す。元のファイルは上書きしない。
- 正常に閉じたときは復元用ファイルを消す。
- 起動時に復元用ファイルが残っていれば、異常終了とみなして「復元しますか」と尋ねる。
- 自動保存は別スレッドで行い、編集を止めない。モデルが不変データ構造なので、ある時点の状態をそのまま書き出せる。

**編集履歴の保存**

- 取り消し履歴はファイルに保存しない。ファイルを閉じると履歴は消える。

## 4. パス編集

パスは3次ベジェ曲線で統一する。アンカーポイントは位置と2本のハンドルを持ち、種別はコーナー / スムーズ / 対称の3つ。

**ツール**

| ツール | 動作 |
| --- | --- |
| 選択 | オブジェクト単位の選択・移動・バウンディングボックス変形 |
| ダイレクト選択 | アンカー・ハンドル・セグメント単位の選択と編集 |
| ペン | クリックでコーナー、ドラッグでスムーズ。Altでハンドル分離、既存パスの端点から継続、セグメント上クリックでアンカー追加、アンカー上クリックで削除 |
| 曲線 | 通過点を指定して滑らかな曲線を自動生成 |
| 鉛筆 | フリーハンド入力を許容誤差つきでベジェにフィット |
| 図形 | 長方形、角丸長方形、楕円、多角形、スター、直線。ライブシェイプとして後から数値を再編集できる |
| はさみ / ナイフ | パスの切断 |
| シェイプ形成 | 重なった領域をドラッグで結合・削除 |
| 変形 | 回転、拡大縮小、シアー、リフレクト(基準点指定、数値入力) |

**パス演算**

- パスファインダー: 合体、前面で型抜き、交差、中マド、分割、刈り込み、合流、切り抜き、アウトライン、背面で型抜き。
- 演算はベジェ曲線のまま行い、結果を折れ線に落とさない。曲線同士の交点計算の数値安定性が最大の難所。
- 複合シェイプ(非破壊の演算)は、破壊的な演算が安定してから対応する。

**パス操作**

- パスのオフセット、線のアウトライン化、単純化、アンカーの整列・平均、連結。
- 線の属性: 線幅、線端、角の形状、マイター制限、破線、線の位置(中央 / 内側 / 外側)、可変線幅プロファイル。

**スナップと補助**

- スマートガイド(他オブジェクトの端・中心・延長線への吸着)、グリッド、ガイド、ポイントへのスナップ。
- アウトライン表示モード(塗りを消してパスだけを表示)。

### 4.1 データモデル

**座標系**

- 単位はポイント(1pt = 1/72インチ)。表示単位(mm、px、インチ)は入出力時に換算する。
- 数値は倍精度浮動小数点。
- 原点は左上、X軸は右向き、Y軸は下向き。PDFの読み書き時だけY軸を反転する。
- オブジェクトは3×2のアフィン変換行列を持つ。パスの座標は変形を適用済みの値で保存し、行列はグループ・シンボル・画像・テキストで使う。

**アンカーポイント**

| フィールド | 内容 |
| --- | --- |
| position | アンカーの位置(絶対座標) |
| handleIn | 入るハンドル(アンカーからの相対座標。ゼロならハンドルなし) |
| handleOut | 出るハンドル(同上) |
| kind | corner(独立)/ smooth(同一直線上、長さは独立)/ symmetric(同一直線上、長さも同じ) |

アンカーを動かすとハンドルは自動で追従する。smooth と symmetric の制約は編集操作の時点で適用し、保存データ上は両ハンドルの値をそのまま持つ。

**パス**

- パス = アンカーの配列 + closed フラグ。セグメントは隣り合う2アンカーの handleOut と handleIn から決まる3次ベジェ。両方ゼロなら直線。
- 複合パス = パスの配列 + 塗りつぶし規則(nonzero / evenodd)。
- アンカー1つだけのパス(孤立点)を許す。Illustratorと同じく、クリーンアップ機能で削除できる。

**ライブシェイプ**

- 長方形(幅、高さ、4隅それぞれの角丸半径と角の種類)、楕円(幅、高さ、扇形の開始角と終了角)、多角形(辺の数、半径、角丸)、スター(頂点数、外半径、内半径)、直線(長さ、角度)。
- ライブシェイプは「パラメータ + 回転を含む変形行列」を保持し、パスは描画時に生成する。
- アンカーを直接編集した、または形が保てない変形(シアーなど)をした時点で、通常のパスに展開する。展開は取り消せる。

操作はIllustratorに合わせる。下表のキーはWindows・Linuxの表記で、macOSではCtrlをCommand、AltをOptionに読み替える。

- 選択中のアンカーに対し、コントロールバーからコーナー/スムーズの切り替え、アンカーの削除、パスの切断、端点の連結ができる。

### 4.3 パス演算エンジン

パス演算は差し替え可能なインターフェースの裏に置き、最初の実装にはSkiaのPathOpsを使う。

**インターフェース**

- 入力: 複合パス2つ(または複数)と演算の種類。出力: 複合パスの配列、または失敗。
- 基本演算は和・差・積・排他的論理和の4つ。パスファインダーの10種はこの4つと「分割」から組み立てる。
- モデルのパス型とSkiaのパス型の変換はこの層だけで行い、他の層にSkiaの型を出さない。
- 失敗した場合は元のオブジェクトを変更せず、利用者にエラーを表示する。黙って壊れた結果を返さない。

**パスファインダーの対応**

| 機能 | 実現方法 |
| --- | --- |
| 合体 | 全オブジェクトの和 |
| 前面で型抜き | 最背面から、それより前面の和を引く |
| 背面で型抜き | 最前面から、それより背面の和を引く |
| 交差 | 全オブジェクトの積 |
| 中マド | 排他的論理和 |
| 分割 | 重なりで区切られる全領域を別々のパスにする |
| 刈り込み | 各オブジェクトから、それより前面の和を引く。線は削除 |
| 合流 | 刈り込みの後、同じ塗りの隣接領域を合体 |
| 切り抜き | 最前面との積。最前面は削除 |
| アウトライン | 分割した結果の輪郭を、交点で区切った開いたパスにする |

結果のアピアランスは、Illustratorと同じく演算ごとに決まった側(多くは最前面)のものを引き継ぐ。

**線の位置**

- 中央: 通常の線。
- 内側: 2倍幅の線を描き、パス自身の形でクリップする。
- 外側: 2倍幅の線を描き、パスの外側だけが残るようにクリップする。
- 内側と外側は閉じたパスでのみ選べる。開いたパスでは中央に固定する。
- 線のアウトライン化では、同じ結果になるパスを演算エンジンで生成する。

**テスト方針**

- 際どい入力のテスト集を最初から作る: 辺が重なる、1点で接する、ほぼ平行、自己交差、極端に小さい・大きい座標、同一形状どうし。
- 検証は「結果の面積が理論値と一致するか」と「描画結果の画像比較」の2本立て。
- PathOpsが失敗した入力は記録して残す。失敗が特定の形状に集中するなら前処理で回避し、広範囲なら自前実装への置き換えを検討する。

## 5. 文字組み

テキストは編集可能なまま保持し、描画時にシェーピングとレイアウトを行う。日本語組版は[日本語組版処理の要件(JLReq)](https://www.w3.org/TR/jlreq/)を基準にする。

**テキストオブジェクト**

| 種別 | 内容 |
| --- | --- |
| ポイント文字 | クリック位置から始まり、自動で折り返さない |
| エリア内文字 | 任意の閉じたパスの内側で折り返す。複数エリア間のスレッド(あふれた文字を次のエリアへ流す) |
| パス上文字 | パスに沿って配置。開始位置、反転、文字の向きを調整 |

すべての種別で横組みと縦組みに対応する。

**文字属性**

- フォント、スタイル、サイズ、行送り、カーニング(メトリクス / オプティカル / 手動)、トラッキング、ベースラインシフト、水平・垂直比率、文字回転。
- OpenType機能: 合字、異体字、プロポーショナルメトリクス、字形切り替え(旧字体、等幅、プロポーショナル)。バリアブルフォントの軸指定。
- 字形パネルから異体字を選んで挿入。異体字セレクタ(IVS、例: 一点しんにょうの「辻」)で指定された字形を、入力・表示・保存・書き出しで保つ。
- 合成フォント: かな、漢字、全角約物、半角欧文、数字などの文字の種類ごとに別のフォントを割り当て、1つのフォントとして使う。種類ごとにサイズ比率とベースラインの調整を持つ。ドキュメントに保存する。

**段落属性**

- 行揃え(左 / 中央 / 右 / 均等配置各種)、インデント、段落前後のアキ、タブ。
- 文字スタイル・段落スタイルを定義して再利用。

**日本語組版**

- 禁則処理(行頭禁則・行末禁則・分離禁止。強い / 弱い のセットと独自定義)。
- 文字組みアキ量設定(約物の前後、和欧間のアキ)。
- 縦中横、ルビ、圏点、割注。
- 文字ツメ、行末の約物ぶら下がり。
- 縦組み時の字形切り替えと欧文回転。

**その他**

- テキストのアウトライン化(パスへの変換)。アウトライン化したパスは元のテキストを隠して持ち、後から文字に戻せる(7.5)。
- フォントが見つからない場合の代替表示と置換ダイアログ。
- IME入力中の未確定文字列の表示。

### 5.1 テキストエンジン

テキストエンジンは自作する。Qtのテキスト機能は使わず、HarfBuzz・FreeType・ICUを部品として組み立てる。キャンバス上の文字はすべてこのエンジンで組み、Skiaにはグリフ単位で描画を渡す。

**処理の流れ**

1. 段落分割: テキストを改段落で区切る。
2. ラン分割: 文字スタイルの境界、書字方向(ICUの双方向アルゴリズム)、スクリプト、フォントフォールバックの境界で区切る。
3. シェーピング: ランごとにHarfBuzzでグリフ列と送り幅を得る。OpenType機能と縦組み用の字形切り替えはここで指定する。
4. アキの挿入: 文字クラス(約物、和字、欧字、数字など)の並びを見て、アキ量設定に従い字間を調整する。
5. 行分割: 改行可能位置(ICUの行分割 + 禁則)から行を決める(5.3)。
6. 行内配置: 行揃え、均等配置の伸縮、ぶら下がりを適用する。
7. 配置: ポイント文字は基点から、エリア内文字はパスの内側の帯ごとに、パス上文字はパスの長さに沿って置く。

**データモデル**

- テキストオブジェクト = 種別(ポイント / エリア / パス上)+ 組み方向(横 / 縦)+ ストーリーへの参照。
- ストーリー = 文字列(UTF-8で保存、内部処理はコードポイント単位)+ 文字スタイルの区間リスト + 段落スタイルの区間リスト。スレッドでつながった複数のエリアは1つのストーリーを共有する。
- レイアウト結果(グリフ位置)は保存しない。開くたびに組み直す。フォントが変わると組みが変わるため、欠落フォントは必ず警告する。

**編集**

- カーソル移動と選択は書記素クラスタ単位(ICU)。結合文字や絵文字の途中にカーソルを置かない。
- IMEの未確定文字列は下線付きでその場に表示し、変換候補ウィンドウの位置をカーソルに合わせる。
- 縦組みではカーソルキーの向きを組み方向に合わせる(上下が文字送り、左右が行送り)。

### 5.2 フォント管理

フォントの入手元は2つ。OSにインストール済みのフォントと、Fontsource・Google Fonts経由で取得するオープンなフォント。

**OSフォント**

- 起動時に列挙する(WindowsはDirectWrite、LinuxはFontconfig、macOSはCore Text)。列挙結果はキャッシュし、次回起動時は変更分だけ更新する。
- ドキュメントにはファミリー名・スタイル名・PostScript名を保存する。フォントファイルは埋め込まない。

**オンラインフォント(Fontsource / Google Fonts)**

Adobe Fontsのように、アプリ内からフォントを探して有効化できる。

- 一覧: フォントパネルの「フォントを探す」タブを開くと、FontsourceのAPI(`https://api.fontsource.org/v1/fonts`)からカタログを読み込む。APIキーは不要。ファミリー名での検索、分類と対応言語での絞り込み、プレビュー表示ができる。カタログは設定フォルダにキャッシュし、オフラインでも検索できる。
- ダウンロード: 選んだファミリーの太さ・斜体ごとにTTFを取得する。Google提供のフォントはGoogle FontsのCSS API(`fonts.googleapis.com/css2?family=…`)でTTFのURLを調べて取得する。それ以外はFontsourceのCDN(`cdn.jsdelivr.net/fontsource/fonts/<id>@latest/<subset>-<太さ>-normal.ttf`)から取得する。
- 検証: 取得したファイルがフォントとして読めるかを確かめてから使う。読めなければ破棄してエラーを表示する。
- 保存: 設定フォルダの `fonts/<id>/` に保存する。OSにはインストールしない。一度取得したフォントは再ダウンロードせず、Leinwand内ではOSフォントと同じ一覧に並ぶ。
- ライセンス: フォントと同じフォルダに `ファミリー名-LICENSE.txt` を置く。中身は著作権表示とライセンス全文(OFL-1.1 と Apache-2.0 の場合)。それ以外のライセンスは、ライセンス名とFontsourceのページへのリンクを記す。パネルにもライセンス名を表示する。
- 有効化したフォントは一覧から無効化(削除)できる。
- 組版用途の確認事項: CDNのファイルはサブセット単位で分かれている。日本語フォントで必要なグリフがそろうか、縦組み用字形やプロポーショナルメトリクスなどのOpenType機能が残っているかを、段階4の着手時に検証する。不足する場合は、完全なフォントファイルの入手元を別に用意する。

**フォントが見つからない場合**

1. ドキュメントを開いたとき、保存されたフォント名がOSにもLeinwandのフォルダにもなければ、欠落フォントの一覧を表示する。
2. その名前がFontsourceのカタログにあれば「有効化」ボタンを出し、押すと自動で取得して組み直す。
3. なければ、代替フォントで表示し、該当箇所をハイライトする。利用者は置換ダイアログで別のフォントを割り当てられる。

**フォールバック**

- 指定フォントにないグリフは、言語ごとのフォールバックリストから補う。日本語の初期設定は源ノ角ゴシック(同梱)。
- フォールバックで表示した文字は、設定でハイライトできる。

### 5.3 行分割と実装の段階

行分割は、Illustratorの「単数行コンポーザー」に相当する方式から始める。段落全体で最適化する「段落コンポーザー」は後回しにする。

**単数行コンポーザー**

1. 行頭から、行幅に収まる最後の改行可能位置を探す。
2. その位置が禁則に反する場合は、追い込み(字間を詰めて行内に収める)か追い出し(次の行へ送る)で解決する。どちらを優先するかは禁則処理の設定に従う。
3. 均等配置の場合、行内のアキを伸縮して行幅に合わせる。伸縮の優先順位と上限はアキ量設定に従う。
4. 次の行へ進む。前の行には戻らない。

**実装の段階**

| 段階 | フェーズ | 内容 |
| --- | --- | --- |
| 1 | 2 | ポイント文字(横組み)、文字属性、基本の段落属性、OSフォント、フォールバック、IME、アウトライン化 |
| 2 | 3 | エリア内文字、スレッド、行分割、禁則処理、均等配置、文字スタイルと段落スタイル |
| 3 | 3 | 縦組み、縦中横、アキ量設定、文字ツメ、ぶら下がり、パス上文字、ルビ(モノ / グループ / 熟語)、圏点 |
| 4 | 3 | オンラインフォント連携、字形パネル、異体字セレクタ(IVS)、合成フォント、バリアブルフォント |
| 5 | 4 | 割注、段落コンポーザー |

各段階の終わりに、JLReqの該当項目と、同じ文章をIllustratorで組んだ結果との見比べで確認する。

## 6. ファイル互換

SVGとPDFは読み書き両対応、.ai は読み込みのみを目標にする。

| 形式 | 読み込み | 書き出し | 備考 |
| --- | --- | --- | --- |
| 独自形式 | ○ | ○ | 全情報を保持する唯一の形式 |
| SVG | ○ | ○ | 最優先。往復で見た目が変わらないことを目標 |
| PDF | ○ | ○ | 編集可能なオブジェクトとして取り込む |
| .ai | △ | △ | 独自データで読める部分を読み、残りはPDF互換データで補う。書き出しはPDF互換の .ai だけ(フェーズ4) |
| EPS | △ | × | 優先度低。PostScriptインタプリタが必要 |
| PNG / JPEG / WebP | ○(配置) | ○ | アートボード単位・選択範囲単位・倍率指定 |

**SVG**

- 読み込み: パス、基本図形、グループ、変形、グラデーション、パターン、クリップ、マスク、テキスト、CSSスタイル、use 要素に対応。フィルターは主要なものから。
- 書き出し: テキストを保持するかアウトライン化するか、小数点桁数、スタイルの出力方法(属性 / CSS)を選べる。
- モデルに対応しない要素は「不明要素」として保持し、再書き出し時にそのまま出力する。

**PDF**

- 読み込み: ページをアートボードに、描画命令をパス・テキスト・画像に変換。フォント埋め込みがある場合は字形を保持。
- 書き出し: フォントのサブセット埋め込み、CMYKとスポットカラー、ICCプロファイル、トンボと裁ち落とし(日本式トンボを選べる、7.5)。PDF/X-1a と PDF/X-4 はフェーズ3。

**.ai**

- .ai の独自データ部分は仕様が非公開だが、旧版の公開仕様と同じ骨組みのテキスト形式で、レイヤー構造・パス・色・アピアランス・効果の設定・テキストの本文が読める(調査は [ai-format-notes.md](ai-format-notes.md))。この部分を読み、モデルに対応づけられるものは編集できる形で取り込む。
- 独自データで読めない部分は、「PDF互換ファイルを作成」で入っているPDF互換データの描画結果で補う。補った部分は読み込みレポートに「近似」として出す。
- ネイティブの .ai 書き出し(Illustratorの独自データを書くこと)は行わない。「.ai で欲しい」と言われたときの受け渡し用に、中身がPDFの「PDF互換の .ai」の書き出しをフェーズ4で用意する(Illustratorで開けるが、ライブシェイプや文字の編集性の一部は失われる)。

**共通**

- クリップボード: 他アプリとのコピー&ペーストはSVGとPDFの両形式で行う。
- 互換性テスト: 形式ごとにサンプルファイル集を用意し、読み込み→書き出し後の描画結果を画像比較する。

### 6.1 SVG

変換は「SVG ⇔ Leinwandのモデル」の専用モジュールで行う。読み込みはSVG 1.1を基準にし、SVG 2で広く使われている機能(`paint-order`、`mix-blend-mode` など)を足す。

**読み込みの対応**

| SVGの要素・属性 | Leinwandでの扱い |
| --- | --- |
| `path`、`rect`、`circle`、`ellipse`、`line`、`polyline`、`polygon` | パス。`rect` と `ellipse` はライブシェイプとして取り込む |
| `g` | グループ。Inkscapeのレイヤー属性が付いた `g` はレイヤーにする |
| `transform` | パスは座標に適用する。グループ・画像・テキストは行列として保持する |
| `fill`、`stroke` と線の各属性 | アピアランスの塗りと線 |
| `linearGradient`、`radialGradient` | グラデーション |
| `pattern` | パターン(フェーズ3まではグループに展開) |
| `clipPath`、`mask` | クリッピングマスク、不透明マスク |
| `text`、`tspan`、`textPath` | ポイント文字、パス上文字 |
| `image` | 画像(埋め込みまたはリンク) |
| `use`、`symbol` | シンボルとインスタンス |
| `style` 要素、`class`、インラインスタイル | CSSを解決して各属性に反映する。対応するセレクタは要素・クラス・ID・子孫まで |
| `filter` | ぼかしとドロップシャドウはライブ効果にする。それ以外は未対応要素として保持する |
| アニメーション、スクリプト、`foreignObject` | 未対応要素として保持する |

- 弧(`A` コマンド)と2次ベジェは、読み込み時に3次ベジェへ変換する。
- 未対応要素は元のXMLのまま保持し、再書き出し時に同じ位置へ出力する。編集はできない。

**書き出しの設定**

| 設定 | 選択肢(太字が初期設定) |
| --- | --- |
| テキスト | **テキストのまま** / アウトライン化 |
| スタイル | **プレゼンテーション属性** / インラインスタイル / CSSクラス |
| 小数点以下の桁数 | 1〜7(**3**) |
| 画像 | **埋め込み** / リンク |
| 範囲 | **アートボードごと** / 選択範囲 / 全体 |
| Leinwandのメタデータ | **含めない** / 含める |
| 圧縮 | **なし** / 最小化(空白と既定値の属性を省く) |

**メタデータの埋め込み**

- 「含める」を選ぶと、Leinwand独自の名前空間の属性と要素で、SVGに収まらない情報を書き添える。対象はレイヤー名とレイヤー構造、アピアランススタック、ライブシェイプのパラメータ、CMYKとスポットカラーの値、文字組みの設定。
- 見た目は標準のSVGだけで再現できるようにし、メタデータは追加情報にとどめる。他のソフトで開いても表示は変わらない。
- Leinwandで開き直すと、メタデータから元の構造を復元する。他のソフトで編集されて見た目とメタデータが食い違う場合は、見た目を正とする。

### 6.2 PDFと .ai

PDFの読み込みはPDFiumでページの描画オブジェクトを取り出し、Leinwandのモデルへ変換する。書き出しはSkiaのPDFバックエンドから始め、CMYKとスポットカラーが必要になるフェーズ3で専用の書き出し処理に置き換える。SkiaのPDFバックエンドはCFFベースのOpenTypeフォントをType3で出すため(M8の検証)、専用の書き出し処理ではCFFもフォントとして埋め込む。

**読み込みの変換規則**

| PDFの内容 | Leinwandでの扱い |
| --- | --- |
| ページ | アートボード。複数ページは読み込むページを選ぶ(全ページ / 範囲指定) |
| パス(塗り、線、クリップ) | パス、クリッピンググループ |
| テキスト | 下の「テキストの扱い」に従う |
| 画像 | 埋め込み画像。色空間は保持する |
| 色(DeviceRGB、DeviceCMYK、ICCBased、Separation) | 元の色空間の値を保持し、画面にはRGBへ変換して表示する |
| 透明、描画モード、ソフトマスク | 不透明度、描画モード、不透明マスク |
| グラデーション(軸、放射) | グラデーション |
| メッシュグラデーション、タイリングパターン | フェーズ4まではラスター画像化し、未対応要素として報告する |
| オプショナルコンテンツ(レイヤー) | レイヤー |
| フォーム、注釈、リンク | 読み込まず、未対応要素として報告する |

**テキストの扱い**

読み込みダイアログで次の3つから選ぶ。初期設定は「自動」。

| 選択肢 | 動作 |
| --- | --- |
| 自動 | 同じフォントが手元(OSまたはLeinwandのフォントフォルダ)にあれば編集可能なテキスト、なければアウトライン |
| すべてテキスト | フォントがなければ代替フォントで表示し、欠落フォントとして警告する |
| すべてアウトライン | PDFに埋め込まれた字形からパスを作る。見た目は必ず一致する |

- PDFのテキストは1文字ずつ、または語ごとに位置指定されていることが多い。編集可能なテキストにする場合、同じ行・同じ書式で隣り合う断片を1つのポイント文字にまとめる。段落や折り返しは復元しない。
- 埋め込みフォントがサブセットで、文字コードへの対応表がない場合は、その部分だけアウトラインにする。

**書き出しの設定**

| 設定 | 選択肢(太字が初期設定) |
| --- | --- |
| 範囲 | **全アートボード(1アートボード = 1ページ)** / 範囲指定 |
| フォント | **サブセット埋め込み** / アウトライン化 |
| 画像 | **元の解像度** / ダウンサンプル(解像度指定) |
| トンボと裁ち落とし | **なし** / あり(幅指定) |
| カラー | **ドキュメントの値のまま** / RGBに変換(フェーズ3でPDF/X-1a・X-4、フェーズ4でICCによるCMYK変換を追加) |

**.ai**

- PDFの `/PieceInfo /Illustrator` にある独自データ(`AIPrivateData`。新しい版は Zstandard、古い版は deflate で圧縮)を展開して読む。レイヤー、グループ、複合パス、クリップ、パス、色(CMYKとRGBの値)、アピアランスの塗りと線、内側・外側の線は、独自データから編集できる形で取り込む。
- ライブ効果は、Leinwandに同じ効果があれば設定値ごと対応づける。ない効果は、その部分をPDF互換データの描画結果で置き換え、「近似」としてレポートに出す。
- テキストは本文を独自データから取り、書式はPDF互換データの描画結果(フォント、サイズ、位置)と突き合わせて決める。フォントがなければアウトラインにする(PDFと同じ)。
- 独自データが読めない、または版が想定と違う場合は、PDF互換データだけで読み込む(読み込みダイアログとテキストの扱いはPDFと同じ)。
- PDF互換データを含まない .ai は、独自データだけで読める範囲を読み込み、読めなかった要素をレポートに出す。
- 古い形式(PostScriptベース、バージョン8以前)はEPSと同じ扱いで、優先度は低い。

### 6.3 読み込みレポートと互換性テスト

読み込みで対応できなかった要素は黙って捨てず、必ず利用者に知らせる。

**読み込みレポート**

- SVG・PDF・.ai の読み込み後、対応できなかった要素が1つでもあれば、レポートのパネルを表示する。なければ何も出さない。
- 一覧の各行は「種類、件数、どう処理したか」を示す。処理は次の4つのどれか。

| 処理 | 意味 |
| --- | --- |
| 保持 | 編集はできないが、元のデータを残してあり、同じ形式で書き出せば出力される |
| 近似 | 見た目が近い別の表現に置き換えた(例: 未対応の効果を画像化) |
| 変換 | 見た目は同じだが編集方法が変わった(例: テキストをアウトライン化) |
| 破棄 | 読み込まなかった(例: スクリプト、フォーム) |

- 行をクリックすると、該当するオブジェクトをキャンバス上で選択する(破棄を除く)。
- レポートはドキュメントを閉じるまで、メニューから開き直せる。
- 書き出し時も同じ考え方で、書き出し先の形式で表現できない要素があれば、書き出し前に一覧を見せる。

**互換性テスト**

- 形式ごとにテスト用ファイル集をリポジトリに置く。SVGは公式のテストスイートと、Illustrator・Inkscape・Figmaから書き出した実例。PDFは各ソフトの書き出しと、印刷入稿用の実例。.ai はPDF互換ありとなしの両方(利用者の作品はリポジトリに入れず、同じ要素を持つテスト用ファイルを作る)。
- 自動テストは3種類。

| テスト | 内容 |
| --- | --- |
| 描画の一致 | 読み込んで描画した画像を、基準の画像(SVGはブラウザ、PDFはPDFiumの描画)と比べる |
| 往復の安定 | 読み込み→書き出し→再読み込みで、描画結果が変わらないこと |
| レポートの固定 | 各ファイルの読み込みレポートの内容を記録し、意図せず変わったら検出する |

- 画像比較は完全一致ではなく、差分の割合がしきい値以下なら合格とする。アンチエイリアスの差を許すため。
- 利用者から報告された「開けないファイル」「見た目が崩れるファイル」は、許可を得てテスト集に加える。

**UI構成**

- 左にツールバー、右にパネル群(プロパティ、レイヤー、アピアランス、文字、段落、スウォッチなど)、上部にコントロールバー、中央にキャンバス。
- パネルはドッキング・タブ化・フローティングができ、配置をワークスペースとして保存できる。
- 操作体系はほぼIllustrator互換とする。ツールの種類と挙動、修飾キーの意味、メニュー構成、パネルの名前と構成、キーボードショートカットをIllustratorに合わせる。ショートカットは変更可能。Adobeのアイコンや画像などの素材は使わず、見た目はSpectrumのガイドラインに沿って自作する。

**デザイン言語**

UIのデザイン言語はAdobeの[Spectrum](https://spectrum.adobe.com/)に準拠する。版は現行のSpectrum 2を採用する。Qt向けの公式実装はないため、公開されているデザイントークンを取り込み、Qt側のコンポーネントは自作する。

| 要素 | 方針 |
| --- | --- |
| 色・余白・角丸・サイズ | [@adobe/spectrum-tokens](https://www.npmjs.com/package/@adobe/spectrum-tokens)(Apache License 2.0)のJSONをビルド時にQtのテーマ定義へ変換する |
| コンポーネント | ボタン、テキストフィールド、スライダー、ピッカー、タブ、ツールチップなどをSpectrumのガイドラインに沿って自作する |
| テーマ | ライトとダークの両方。スケールはデスクトップ向けのmedium |
| UIフォント | Adobe CleanはAdobe製品専用のため使えない([Spectrumのフォント規定](https://spectrum.adobe.com/page/fonts))。代わりにSource Sans 3と源ノ角ゴシック(どちらもSIL OFL)を使う |
| アイコン | Spectrumのワークフローアイコン(@adobe/spectrum-css-workflow-icons、Apache License 2.0、Spectrum 2対応のSVG)を使う。ペンツールなど足りない図柄は、同じ20×20の枠と線幅の規則で自作する |
| 表記 | 「Spectrum」「Adobe」は商標のため、アプリ名やロゴには使わない。配布時はApache 2.0のNOTICEを同梱する |

**パネルの共通仕様**

- ドッキング、タブ化、フローティング、アイコンへの折りたたみができる。
- 数値入力欄は、単位つきの入力(`10mm`、`2in`)と四則演算(`100+20`、`50/2`)を受け付け、ドキュメントの単位に換算する。上下キーで増減、Shiftで10倍。
- 複数のオブジェクトを選択していて値が異なる場合、入力欄は空欄で表示する。値を入れると全オブジェクトに適用する。
- パネルの変更は即座にキャンバスへ反映し、スライダーのドラッグ中の変更は1回の取り消しにまとめる。

### 7.3 環境設定と多言語対応

**環境設定**

環境設定は1つのダイアログにまとめ、左の一覧で分類を切り替える。

| 分類 | 主な項目 |

| 単位 | 一般、線、文字、東アジア言語の文字の単位 |
| ガイド・グリッド | 色、スタイル、グリッドの間隔と分割数 |
| スマートガイド | 表示する項目(整列ガイド、アンカー、計測ラベル)、スナップの許容範囲 |

| パフォーマンス | GPU描画の切り替え、取り消しの回数の上限 |

- 設定はJSONファイルとして、OSごとの設定フォルダに保存する(Windowsは `%APPDATA%\Leinwand`、macOSは `~/Library/Application Support/Leinwand`、Linuxは `~/.config/leinwand`)。

- キーボードショートカットは別ダイアログで編集し、セットとして保存・書き出し・読み込みができる。

**テーマ**

- Spectrum 2のライトとダークの2種類。初期設定はダーク。Illustratorの4段階の明るさ設定は再現しない。
- キャンバスの背景色はテーマとは別に設定できる。

**多言語対応**

- UIの言語は日本語と英語を最初から用意する。文言はソースコードに直接書かず、Qtの翻訳の仕組み(.tsファイル)で管理する。
- 用語はIllustratorの日本語版・英語版に合わせる(パスファインダー / Pathfinder、アピアランス / Appearance など)。
- 数値の書式、単位の初期値は言語設定に従う。

### 7.4 プリント

プリント機能はフェーズ2で、PDF書き出しと一緒に実装する。

| 設定 | 内容 |
| --- | --- |
| プリンター | OSに登録されたプリンターから選ぶ。プリンター固有の設定はOSのダイアログを開く |
| 用紙 | サイズ、向き(縦 / 横 / 自動) |
| 範囲 | すべてのアートボード / 範囲指定 / 選択中のアートボード。アートボードを無視して全体を1枚に刷ることもできる |
| 拡大・縮小 | 実寸 / 用紙に合わせる / 倍率指定 |
| 配置 | 用紙上の位置(9点から選ぶ、または数値) |
| タイル | 用紙より大きいアートワークを複数枚に分割する。重なり幅を指定 |
| トンボと裁ち落とし | トンボ、レジストレーションマーク、裁ち落とし幅 |
| 部数 | 部数、丁合い |

- ダイアログの左にプレビューを表示し、用紙に対するアートワークの位置を確認できる。
- 出力はPDF書き出しと同じ描画経路を使う。プリンターへの送り方はOSごとに異なるため、実装方法はフェーズ2の最初に検証する。
- 色はRGBで送る(CMYKドキュメントはRGBに変換して送る)。CMYKの分版出力は対象外とする。

## 9. 起動と配布

起動時はスプラッシュスクリーン、ウェルカムスクリーンの順に表示する。構成はAdobe製品に倣う。

**スプラッシュスクリーン**

- 表示内容: アートワーク、アプリ名、バージョン、著作権表示、読み込み中の処理名と進捗バー。アートワークは作成済みの1200×640の画像を使う(暗い紺の背景、左下にロゴタイプ「Leinwand」(フォントはOutfit Bold、SIL Open Font License)、右上から流れる紫・青・緑・黄・赤の5色の波、紫の波にパスのアンカーとハンドルの図柄)。バージョンはロゴタイプの右にベースラインを揃えて、著作権表示は左下に、処理名と進捗バーは右下に重ねる。
- 処理名は内部の初期化ステップをそのまま出す(例:「フォントを列挙中…」「設定を読み込み中…」「ワークスペースを復元中…」)。各初期化モジュールが自分の名前を通知する仕組みにし、表示用の文言を別に管理しない。
- 枠なしウィンドウで画面中央に表示し、メインウィンドウの準備ができたら閉じる。

**ウェルカムスクリーン**

- メインウィンドウとは独立したウィンドウで表示する。
- 載せるもの: 新規作成(プリセット一覧とカスタムサイズ)、ファイルを開く、最近使ったファイル(サムネイル付き、グリッド/リスト切り替え)。
- 新規作成プリセット: 印刷(A4、A3、B5、はがき、名刺)、Web(1920×1080 など)、アイコン、カスタム。単位・カラーモード・裁ち落としを指定できる。
- 環境設定で「起動時にウェルカムスクリーンを表示する」を切り替えられる。オフのときは空のメインウィンドウで起動する。
- ファイルを指定して起動した場合(ダブルクリック、ドラッグ&ドロップ)は表示しない。

**インストーラー**

| OS | 形式 | 状態 |
| --- | --- | --- |
| Windows | exe形式のWebインストーラー。Inno Setupで作成 | 決定 |
| Linux | deb形式 | 決定 |
| macOS | dmg形式のディスクイメージ(Apple Silicon)。アドホック署名のみで、Appleの公証は受けない | 決定 |

- Windowsインストーラーの内容: インストール先の選択、スタートメニューとデスクトップのショートカット、ファイルの関連付け(.lwd はLeinwandに関連付ける。.svg .ai .pdf は「プログラムから開く」の候補に登録するだけで、既定のアプリは変更しない)、アンインストーラーの登録。QtとSkiaのランタイムを同梱する。
- 自動アップデートは当面入れない。バージョン確認だけ後のフェーズで追加し、更新はインストーラーの再実行で行う。

**Webインストーラー(Windows)**

配布するexeは小さな本体だけを持ち、アプリ本体は実行時にダウンロードする。

1. 起動時にGitHub Releasesからバージョン一覧(JSON)を取得する。各リリースにパッケージ本体とSHA-256のハッシュ値を添付しておく。
2. 既定では最新版が選ばれている。「他のバージョン…」ボタンで過去バージョンの一覧を開き、選び直せる。
3. 選んだバージョンのパッケージをダウンロードし、SHA-256で検証してからインストールする。

- Inno Setupのダウンロード機能と、スクリプトで作るカスタムページで実現する。
- 別バージョンが入っている場合は上書きする。複数バージョンの共存は扱わない。
- ポータブル版は当面作らない。コード署名は後のフェーズで行う。それまではSmartScreenの警告が出ることを配布ページに明記する。
- macOS版は、Leinwand.app と「アプリケーション」フォルダへのリンクを入れた dmg で配る。Apple Developer Program に入るまでは Developer ID の署名と公証がないため、初回はGatekeeperに止められる。「システム設定 → プライバシーとセキュリティ」の「このまま開く」で許可する手順を配布ページに明記する。

**アプリアイコン**

- 作成済みのSVG(1024×1024)を原版とし、リポジトリの resources に置く(濃い色の角丸の四角形に、右上から流れ込む5色の帯と、その1本をなぞる選択中のベジェパス(アンカーとハンドル)の図柄)。
- Windows用に16・24・32・48・256pxを含む .ico、Linux用に各サイズのPNGとSVGを用意する。
- 16〜32pxではパスとハンドルの細い線が消えるため、線を太くした小サイズ用の版を別に作る。小サイズ版では、原版の粒子・光・影のフィルターも外す。
- .lwd ファイル用の文書アイコンも同じ図柄から作る。
