# .ai ファイルの調査メモ

.ai の読み込み(仕様書 6.2、フェーズ3)に向けた調査の記録。実物のファイルを1つ解析した結果(2026-10-03)。ファイルそのものは利用者の作品なのでリポジトリに入れない。テスト用には、同じ要素を持つファイルを別に作る。

## 調べたファイル

- Illustrator 28.7(Windows)で保存。「PDF互換ファイルを作成」が有効。
- アートボード1枚(1152 × 512 px)、レイヤー1つ。
- 中身: 少数のパス(長方形、円、線、多角形)、日本語と欧文のテキスト13個、大きなラスター画像(背景)、グラデーション、乗算と不透明度、フェザーとパスのオフセット、内側の線、クリップ。

## ファイルの構造

.ai は PDF ファイルで、その中に Illustrator 独自のデータが入っている。

| 部分 | 中身 | 読むのに必要なもの |
| --- | --- | --- |
| PDF のページ | 描画結果(パス、テキスト、画像、透明) | PDF の解析(PDFium など、仕様書 6.2 の方針) |
| `/PieceInfo /Illustrator` → `/AIPrivateData1..N` | Illustrator 独自のデータ。ストリームを順につなぐと `%AI24_ZStandard_Data` で始まる | Zstandard の解凍 |
| XMP メタデータ | 作成アプリ、アートボードの大きさ、フォント一覧、スウォッチ一覧 | XML の解析 |

古い版の .ai では独自データが `%AI12_CompressedData`(deflate)だったが、この版では Zstandard になっている。調べたファイルでは 1.5MB が 96MB に展開された(大半は無圧縮のラスター画像)。

## 独自データ(展開後)

展開すると、Illustrator の昔からの PostScript 風のテキスト形式(`%!PS-Adobe-3.0`、`%AI5_FileFormat 14.0`)になっている。Adobe が公開していた旧版の仕様(Illustrator 7 の「Adobe Illustrator File Format Specification」)と同じ骨組みに、後の版の情報が `%_` で始まるコメント行として足されている。

| 要素 | 書き方 | Leinwand のモデルとの対応 |
| --- | --- | --- |
| レイヤー | `%AI5_BeginLayer` … `Lb` … `(名前) Ln` | レイヤー(名前、表示、ロック) |
| パス | `m` `L`/`l` `C`/`c` `v` `y` と描画演算子(`f` `F` `S` `s` `b` `B` `N` `n`) | パス。旧仕様に書かれている |
| グループ、複合パス、クリップ | `u`/`U`、`*u`/`*U`、`q`/`Q` | グループ、複合パス、クリッピンググループ |
| 色 | `XA`/`Xa`(CMYK と RGB の組)、`k`/`K`、`x`/`X`(スウォッチ) | 色(CMYK と RGB の両方の値を持つ) |
| グラデーション | `%AI5_BeginGradient` と `Bb` `Bg` `BB` | フェーズ2のグラデーション |
| アピアランス | `/KnownStyle`、`/ActiveStyle` の中の `Stack Style Filter`、`Fill Style Filter`、`Stroke Style Filter`、`Blend Style Filter` | アピアランススタック(複数の塗りと線、不透明度と描画モード) |
| ライブ効果 | `/BasicFilter` のプラグイン名(`Adobe Fuzzy Mask`、`Adobe Offset Path`、`Adobe Stroke Offset` など)と、その引数の辞書 | フェーズ3のライブ効果。内側の線は `Adobe Stroke Offset`(`StrokeOffsetInside`)で表されており、線の位置に対応づけられる |
| ラスター画像 | `%AI5_BeginRaster` … `XI` と `%%BeginData:`。画素は無圧縮のバイナリ | 画像オブジェクト(まだない) |
| テキスト | オブジェクト側は `/AI11Text`(ストーリー番号とフレーム番号)。本文と書式は `%AI11_BeginTextDocument` に ASCII85 で入っている | フェーズ2〜3の文字 |
| シンボル、ブラシ、パターン | `%AI14_BeginSymbol`、`%AI5_BeginBrushPattern`、`%AI5_BeginPattern` | フェーズ3〜4 |

**テキストについて**: テキストドキュメントは ASCII85 を解くとそのまま読める(圧縮されていない)。Adobe のテキストエンジンの形式で、本文は UTF-16 の文字列として入っていて、13個のテキストすべての本文を取り出せた。ただし書式のキーは名前ではなく番号(95種類)になっている(古い版では `/FontSize` のような名前だった)。番号の意味は公開されていないので、PDF 側の描画結果(フォント、サイズ、位置)と突き合わせて割り出す必要がある。

## 見通し

1. **PDF 側だけを読む(仕様書の方針)**: 見た目はほぼ再現できる。調べたファイルでは、画像オブジェクトと不透明マスクがあれば足りる。レイヤー構造、アピアランス、効果、編集できるテキストは失われる。
2. **独自データも読む**: パス、グループ、レイヤー、色(CMYK の値を含む)、アピアランスの塗りと線、内側の線は、旧仕様と今回の観察で読める見込みが高い。ライブ効果は引数の辞書が読めるので、Leinwand に同じ効果があれば対応づけられる。テキストは本文は取れるが、書式は番号の割り出しが要る。
3. 独自データは、版によって中身が変わりうる。読めない部分は PDF 側の描画結果に頼る(読み込みレポートに「近似」として出す)という組み合わせが現実的。

**決定(2026-10-03)**: 3 の組み合わせで進める。独自データで読める部分を編集できる形で読み、残りはPDF互換部分の描画結果で補う。仕様書 6.1・6.2 と10章を更新した。

## 次に欲しいサンプル

形式の幅を確かめるために、次のようなファイルがあるとよい(作品でなくてよく、テスト用に作ったもので足りる)。

- 「PDF互換ファイルを作成」を切って保存したもの(独自データだけのファイル)
- CMYK ドキュメント、スポットカラーを使ったもの
- 複数のアートボード、複数のレイヤーとサブレイヤー
- ライブシェイプ(角丸の長方形、多角形)、エリア内文字、パス上文字
- 古い版(CS6 など)で保存したもの
