# フェーズ1 計画

フェーズ1の到達点は「図形とパスを描いて、.lwd とSVGで保存できる」こと。Windows版を最初のリリース(v0.1.0)としてGitHub Releasesに公開するところまでを範囲とする。期間は定めず、マイルストーンを順に進める。

## 1. リポジトリ構成とビルド環境

リポジトリは1つにまとめる。モデル層(core)はQtにもSkiaにも依存させず、単体でテストできるようにする。

```text
leinwand/
├─ CMakeLists.txt
├─ CMakePresets.json        ビルド設定(windows-debug、linux-release など)
├─ vcpkg.json               依存ライブラリの一覧
├─ LICENSE                  GPL-3.0-or-later
├─ NOTICE                   使用ライブラリの著作権表示
├─ README.md / README.ja.md
├─ src/
│  ├─ core/                 ドキュメントモデル、コマンド、取り消し履歴(依存なし)
│  ├─ geometry/             ベジェ計算、パス演算のインターフェース
│  ├─ render/               Skiaによる描画、パス演算のPathOps実装
│  ├─ io/                   .lwd の読み書き、SVGの読み書き
│  ├─ platform/             OS固有の処理(フォント列挙、設定フォルダなど)
│  ├─ ui/                   Spectrumのコンポーネント(QML)、テーマ
│  └─ app/                  メインウィンドウ、ツール、パネル、キャンバス(Qt Quick)
├─ resources/               アイコン、スプラッシュ、同梱フォント、翻訳(.ts)
├─ tests/                   単体テスト、描画の画像比較テスト
├─ testdata/                テスト用の .lwd、SVG、基準画像
├─ tools/                   Spectrumトークンの変換スクリプトなど
├─ packaging/
│  ├─ windows/              Inno Setupのスクリプト
│  └─ linux/                deb用の設定(フェーズ1では枠だけ)
├─ docs/                    開発者向けの説明、ファイル形式の仕様
└─ .github/workflows/       CI
```

**依存の向き**

`app` → `ui`、`render`、`io` → `geometry` → `core` の一方向。下の層は上の層を知らない。`platform` は `core` 以外のどこからでも使える。

**ビルド環境**

| 項目 | 内容 |
| --- | --- |
| 言語規格 | C++20 |
| ビルド | CMake + Ninja。設定はCMakePresetsで共有する |
| コンパイラ | WindowsはMSVC(Visual Studio 2022)。LinuxはGCCまたはClang |
| Qt | Qt 6の長期サポート版。公式インストーラーで入れ、LGPLで使えるモジュールだけを使う |
| 依存ライブラリ | vcpkgのマニフェストモードで取得する(Skia、後のフェーズでHarfBuzz、FreeType、ICU、Little CMS) |
| テスト | Catch2。CTestから実行する |
| 書式と静的解析 | clang-format、clang-tidy。設定ファイルをリポジトリに置く |
| エディタ | 指定しない。Qt Creator、Visual Studio、VS CodeのどれでもCMakePresetsから開ける |

- Skiaはビルドに時間がかかる。vcpkgのSkiaで必要な機能(Vulkan、PDF、PathOps)が有効にできるかをM0で確かめる。できなければ、Skiaだけ自前でビルドしたものを使う。
- フェーズ1で必要な外部ライブラリは、Qt、Skia、Catch2、JSONとZIPの読み書き用ライブラリまで。テキスト関連は入れない。

## 2. マイルストーン

8つのマイルストーンを順に進める。各マイルストーンは、完了条件を満たしたら次へ進む。

|  | マイルストーン | 内容 | 完了条件 |
| --- | --- | --- | --- |
| M0 | 環境構築と検証 | リポジトリ作成、CMakeとvcpkgの設定、CI。Qt QuickのウィンドウにSkiaで描いたキャンバスを表示する。技術検証3件(下記) | WindowsとLinuxのCIが通る。ウィンドウにSkiaの描画が出る |
| M1 | モデルと描画 | ドキュメントモデル(レイヤー、パス、グループ、アピアランス)、描画、ズームとパン、アートボード1枚 | コードで組み立てたドキュメントが正しく表示され、滑らかに拡大縮小できる |
| M2 | 選択と変形 | 選択ツール、バウンディングボックスでの移動・拡大縮小・回転、コマンドと取り消し/やり直し、重ね順、グループ化、複製、削除 | 複数のオブジェクトを選んで変形し、すべての操作を取り消せる |
| M3 | 図形ツール | 長方形、楕円、多角形、スター、直線。ライブシェイプ。変形パネル | 図形を描き、後から数値で幅・高さ・角丸を変えられる |
| M4 | ペンとダイレクト選択 | ペンツール(4.2の操作表)、ダイレクト選択、アンカーの追加・削除・切り替え、スマートガイドとスナップ、アウトライン表示 | 操作表の全行が動く。任意の曲線を描いて修正できる |
| M5 | 塗りと線、パネル | カラー、スウォッチ、線、レイヤー、プロパティの各パネル。ツールバーとコントロールバー。Spectrumのテーマ(ライト / ダーク)。スポイト | パネルから色と線を変えられる。レイヤーの表示・ロック・並べ替えができる |
| M6 | 保存と読み込み | .lwd の読み書き、自動保存と復元、SVGの読み書き(パス、図形、グループ、変形、塗りと線)、PNG書き出し、読み込みレポート | 保存して開き直すと同じ状態に戻る。SVGの往復テストが通る |
| M7 | 仕上げとリリース | スプラッシュ、ウェルカムスクリーン、環境設定、キーボードショートカット、日本語と英語のUI、アイコン一式、Webインストーラー | v0.1.0をGitHub Releasesに公開し、インストーラーから導入できる |

**M0の技術検証**

M0では、後から変えにくい前提を3つ確かめる。どれかが成立しなければ、M1へ進む前に方針を見直す。

| 検証 | 確かめること | 成立しない場合 |
| --- | --- | --- |
| SkiaとQt Quickの統合 | Qt QuickのシーングラフとSkiaが同じVulkanのコンテキストで描画できるか | テクスチャ経由の受け渡しにする。それも難しければOpenGLを使う |
| 描画性能 | 1万個のパスを表示して、ズームとパンが滑らかに動くか | 描画結果のタイルキャッシュ、画面外オブジェクトの除外を先に設計する |
| ドッキングパネル | KDDockWidgetsの見た目をSpectrumに合わせられるか | ドッキングを自作する。フェーズ1は固定配置のパネルで進める |

仕様書の8章で挙げたベジェ交点計算とテキストシェーピングの検証は、それぞれパスファインダーと文字に着手するフェーズ2の最初に行う。

**フェーズ1に含めないもの**

パスファインダー、文字、グラデーション、マスク、複数アートボード、整列パネル、PDF、Linux版の配布。これらはフェーズ2以降。Linuxではビルドとテストだけ通し続ける。

## 3. CIと開発ルール

**CI(GitHub Actions)**

| ワークフロー | きっかけ | 内容 |
| --- | --- | --- |
| ビルドとテスト | プルリクエスト、mainへのプッシュ | WindowsとLinuxでビルドし、単体テストと画像比較テストを実行する。vcpkgのビルド結果はキャッシュする |
| 書式チェック | プルリクエスト | clang-formatの差分がないことを確かめる |
| リリース | `v` で始まるタグのプッシュ | Windows版をビルドし、パッケージとSHA-256、Webインストーラーを作ってGitHub Releasesに添付する |

- 画像比較テストはGPUのないCI環境で動かすため、SkiaのCPU描画で実行する。GPU描画との差は手元で確認する。
- 公開リポジトリなので、GitHub Actionsの標準ランナーは無料で使える。

**ブランチとコミット**

- `main` は常にビルドとテストが通る状態を保つ。作業は機能ごとのブランチで行い、プルリクエストでCIを通してからマージする。1人で開発する間も同じ手順にする。
- コミットメッセージは英語。1行目に変更の要約、必要なら空行をはさんで理由を書く。
- マイルストーンごとにGitHubのマイルストーンを作り、作業項目はIssueで管理する。

**バージョン番号**

- アプリのバージョンは `メジャー.マイナー.パッチ`。フェーズ1の完了が v0.1.0、フェーズ2が v0.2.0、Illustrator相当に届いた時点で v1.0.0 とする。
- マイルストーンの途中経過は、必要に応じて `v0.1.0-alpha.1` のようなプレリリースとして公開する。Webインストーラーの「他のバージョン…」には正式版だけを並べ、プレリリースは設定で表示を切り替える。
- .lwd の形式バージョンはアプリのバージョンとは別に管理する(仕様書3.3)。v1.0.0までは形式を変える可能性があることをREADMEに明記する。

**コーディング規約**

- 命名と書式はclang-formatとclang-tidyの設定に従う。規約の文書は `docs/` に短くまとめる。
- `core` と `geometry` の公開関数には単体テストを付ける。描画と入出力は、テストデータと基準画像による比較テストで守る。
- ソースファイルの先頭にライセンスの識別子(`SPDX-License-Identifier: GPL-3.0-or-later`)を書く。
