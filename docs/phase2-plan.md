# フェーズ2 計画

フェーズ2の到達点は「ロゴや簡単なイラストが作れる」こと(仕様書8章)。v0.2.0 として GitHub Releases に公開するところまでを範囲とする。期間は定めず、マイルストーンを順に進める。番号はフェーズ1の続き(M8〜)にする。

## 1. 範囲

仕様書から、フェーズ2に割り当てられたものを集めた。

| 領域 | 内容 | 仕様書 |
| --- | --- | --- |
| パス演算 | パスファインダー(形状モード4種、パスファインダー6種)、複合パスの編集 | 4、4.3、7.2 |
| パス編集 | ダイレクト選択の完成(スマートガイドの残り、はさみ、アンカーの整列・平均) | 4、4.2 |
| 整列 | 整列パネル。整列、分布、等間隔。基準は選択範囲 / キーオブジェクト / アートボード | 7、7.2 |
| アートボード | 複数アートボード、アートボードツール、アートボードパネル、サイズプリセット | 7、7.2 |
| グラデーション | 線形と円形。グラデーションパネル、キャンバス上での編集 | 7、7.2 |
| クリップと透明 | クリッピングマスク、不透明マスク、描画モード、透明パネル | 7、7.2 |
| 文字 | 段階1: ポイント文字(横組み)、文字パネル、基本の段落属性、OSフォント、フォールバック、IME、アウトライン化 | 5、5.3 |
| 出力 | PDF書き出し、プリント、SVG のグラデーションとテキスト | 6、7.4 |
| ライブシェイプ | ライブコーナー(角の種類と半径をキャンバス上で編集) | 10 |
| 入稿と制作支援 | 日本式トンボ、入稿チェック(RGB で確かめられる項目)、元の文字を残すアウトライン化、日本の判型のプリセット、同人誌・冊子の表紙テンプレート | 7.5 |

フェーズ2に含めないもの: 複合シェイプ(非破壊の演算)、シェイプ形成ツール、エリア内文字・パス上文字・縦組み・日本語組版(フェーズ3)、PDFと .ai の読み込み(フェーズ3)、アピアランスパネル(フェーズ3)、CMYK ドキュメントと PDF/X(フェーズ3)。

マイルストーンの順番は、検証の結果で入れ替えてよい(たとえばテキストの組み込みに手間がかかるなら M14 を先に始める)。

**M8 の検証**

| 検証 | 確かめること | 成立しない場合 |
| --- | --- | --- |
| パス演算の安定性 | 仕様書 4.3 の際どい入力(辺が重なる、1点で接する、ほぼ平行、自己交差、極端な座標、同一形状どうし)で、Skia の PathOps が正しい結果を返すか。曲線のまま結果を返すか。面積と画像比較で確かめる | 失敗する形が限られていれば前処理(微小なずらし、丸め)で避ける。広く失敗するなら自前の実装を検討する |
| テキストシェーピング | HarfBuzz・FreeType・ICU を vcpkg で Windows・Linux・macOS に入れられるか。日本語と英語の混じった文を HarfBuzz で組み、Skia でグリフとして描けるか。PDF にフォントを埋め込めるか。OS のフォントを列挙できるか(DirectWrite、Fontconfig、Core Text) | Skia にグリフを渡せなければ、FreeType のアウトラインをパスとして描く。PDF の埋め込みができなければ、PDF 書き出しは当面アウトライン化した文字で出す |

## 3. 進め方

- フェーズ1と同じく、作業ブランチ(`m1/core-model`)で進め、マイルストーンのまとまりごとに PR を分ける。
- 新しい依存ライブラリ(HarfBuzz、FreeType、ICU)は M8 の結論が出てから `vcpkg.json` に足す。
- macOS はビルドとテストを CI で通し続ける。macOS 版の配布は、フェーズがある程度固まってから GitHub Releases で行う(v0.2.0 で Windows と一緒に出すかは M15 で決める)。
- .lwd の形式は、グラデーション、マスク、テキストの追加で版を上げる(仕様書3.3)。古い版のファイルは読めるようにする。
