# M8 検証結果

フェーズ2の最初に行う2件の検証(`docs/phase2-plan.md`)の記録。

## 1. パス演算(Skia PathOps)の安定性

**結論: 採用する。** 仕様書 4.3 の際どい入力のほとんどで正しい結果を返し、曲線は曲線のまま残る。問題は原点から遠い座標での精度だけで、変換層の前処理で避けられる。

**方法**: `tests/render/pathops_probe_test.cpp`(通常のテストからは外してある。`render_tests "[pathops-probe]"` で実行)。21 の入力の組それぞれに、和・積・差・排他的論理和の4演算をかけ、結果を3通りで確かめた。

- 画素: 入力をそれぞれ 512×512 でラスタライズして演算した結果と、演算結果のラスタライズを比べる(縁の1画素のずれは許す)。
- 面積: 既知の値(正方形どうし)と比べる。
- 恒等式: |A∪B| + |A∩B| = |A| + |B|、|A−B| = |A| − |A∩B|、|A xor B| = |A∪B| − |A∩B| を、アンチエイリアス付きの 2048×2048 の被覆率で確かめる。

**結果**(Windows、Release ビルド)

| 入力 | 結果 |
| --- | --- |
| 辺を共有する正方形、辺の一部が重なる正方形、角だけで接する正方形、同一の正方形 | 正しい。面積は厳密値と一致 |
| 同一の円、重なる円、外接・内接する円、1e-4 だけ離れた円、同心円 | 正しい |
| 0.001° と 1e-6° だけ回した正方形(ほぼ平行な辺) | 正しい。1e-6° では同一とみなされる |
| 円と接する正方形 | 正しい |
| 一筆書きの星(自己交差)、8の字、ループのある3次曲線 | 正しい |
| 半径 0.01 の円、半径 1e5 の円 | 正しい |
| 60 個の円の和と円(交点多数) | 正しい。1 演算 7〜8ms |
| 細い長方形 40 本と円 | 正しい。1 演算 0.4〜0.5ms |
| 原点から 1e6 離れた半径 10 の円 | 縁で 12〜34 画素ずれる |
| 原点から 1e6 離れた半径 0.1 の円 | 結果が空になる(失敗) |

- 入力が3次ベジェなら、結果も3次ベジェで返る(折れ線にならない)。交点で分割された曲線が返る。
- 失敗の原因は、Skia のパスが座標を 32 ビットの浮動小数点で持つこと。1e6 付近では 1/16pt 刻みになる。モデルは倍精度なので、**変換層で入力全体の中心を原点に移してから float に変換し、結果を戻す**。これで大きな座標の問題はなくなり、残る制約は「入力全体の大きさに対して約 1/10⁷ より細かい形は潰れる」ことだけになる(1m 四方の範囲で 0.1µm 程度)。
- 結果の輪郭は向きがそろっていないことがある(偶奇規則で正しく塗れる形で返る)。モデルに戻すときは塗りの規則も一緒に戻す。

**M9 への引き継ぎ**

- `geometry` に演算のインターフェースを置き、PathOps の実装は `render` に置く(仕様書 4.3)。中心を原点に移す前処理はこの実装の中で行う。
- PathOps の出力には 2 次曲線や有理2次曲線(conic)も現れうる(この検証の入力では区別して数えていない)。変換層では、2 次は 3 次に正確に上げ、conic は近似して 3 次にする。
- この検証の入力を、M9 の際どい入力のテスト集の土台にする(仕様書 4.3 のテスト方針)。
